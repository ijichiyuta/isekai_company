# ADR-0002: §10.2 経済カーブの改訂と設備×品質再投資エンジン

**状態**: 採択 / **日付**: 2026-08-26 / **関連**: 要件 §10.1, §10.2, §18(AC-08/09), M3計画監査(`docs/m3-plan-audit.md`), ADR-0001

## 背景

要件 §10.2 の当初カーブは資産が 100→2,000→40,000→800,000→15,000,000 G（tick 400/1000/1800/2600）と **near-geometric（比が緩やかに増える凸型）** に設計されていた。しかし M2 実装では御用達(15M)到達 0%＝カーブ形状が破綻していた（序盤 +25,637%/終盤 -52%、AC-09 で可視化）。

M3 計画監査（Opus並列3体、実計算裏取り）で、この当初カーブが**現エンジンでは原理的に到達不能**であることが証明された：

- 販売→名声→需要プールの帰還ループは `fame_{t+1} = fame_t · ρ + 定数`、`ρ = 1 + demandPerFame·price/(100·fame_per_sales_g)` の **定数比 ρ の幾何過程**。
- §10.2 当初カーブが各区間で要求する ρ は **漸減**（1.0075→1.0050→1.0038→1.0037）。定数 ρ は漸減 ρ に構造的に一致不能（序盤に合わせると終盤で行き過ぎ、逆も同様）。
- 設備Lv・品質★は**有限上限の一度きり係数ジャンプ**であり ρ に効かない（上限到達後は必ず線形化）。
- 8次元グリッド探索（19,440構成）で全チェックポイント±50%内に収まる構成は **0件**。∞容量・∞品質・0コストの上界でも到達不能。

## 決定

1. **§10.2 を到達可能カーブへメジャー改訂する**（当初の near-geometric を破棄）。改訂カーブは設備Lv×品質★の複利再投資エンジン下で堅実型が実測する中央値（events込み）：資産 100→16K→260K→5.3M→37M G（tick 0/400/1000/1800/2600）、生涯末 ~49M。原案より平坦（less geometric）で、王国御用達(15M)は生涯の約75%地点(tick~2150)で到達する後半マイルストーン。**AC-09 はこの改訂カーブに対して ±50% で測定**する（`gate.dart` の `_curveTargets` を差し替え）。

2. **第2収益ドライバ＝設備レベル×品質★を導入**（`economy.json` に追記、`state.dart`/`engine.dart`/`commands.dart`）：
   - **設備レベル** `equipmentLevel`：週次生産容量を `×(100 + level×equip_step_x100)/100`。`UpgradeEquipment` コマンドで購入、コストは幾何（`equip_cost_base × (equip_cost_mult_x100/100)^level`）、`equip_max_level` 上限。
   - **品質★** `qualityStar`：販売単価を `×quality_mult_x100[star]/100`。`ImproveQuality` コマンドで購入、コストは幾何、`quality_mult_x100` 配列長-1 上限。
   - **発明プレミアム** `invention_price_premium_x100`：発明品の単価を `×premium/100`（C-2是正＝発明品が継続生産で選ばれる）。
   - 位置づけ：**§10.2 に乗せる魔法ではなく**、M2で8Mに頭打ちしていた終盤(-52%)を持ち上げ、御用達到達を可能にする補助ドライバ。名声は `fame_per_sales_g`（20→640）で減速し暴走を止める（events込みの名声ブーストを織り込んだ最終校正値）。

3. **全キーは任意（default＝無効果）**：`economy.json` にキーが無い balance は pre-M3 と byte-identical に振る舞う（`state.dart` の equip/quality フィールドは非default時のみ toJson、fromJson は `?? 0`）。既存の決定論テスト（events-less）は不変。

4. **AC-08（御用達到達≥80%）を hard 化**：再投資エンジンで堅実型到達≈100%・攻め型破産<30%を seed 1/2/999 で満たしたため、hard ゲートに昇格し達成を回帰から守る（`gate.dart`）。

5. **contentHash 破壊を許容（ADR-0001 のメジャー改訂例外）**：`economy.json` に新キーが増え contentHash が変わるため、M2以前の全セーブを `decodeSave` が拒否する（§2.2 rule7）。ADR-0001 の「追記のみ原則」は数値・id の**構造**に関する原則であり、本改訂は経済モデルそのものの**メジャー改訂**＝明示的な例外として記録する。リリース前ゆえ救うべき実セーブは存在しない。

## 帰結

- **良**: 御用達到達 0%→100%（AC-08 hard PASS、500ライフ実測で到達100%・worst到達tick 2344＝536tick余裕）。AC-09 が改訂カーブに対し PASS（既定10ライフでworst≈90%、events乱数で±40%振れうるが300+ライフで≈92%に収束、±50%内）。全 hard ゲート（AC-04/05/07/08）PASS。発明品が継続生産で選ばれるようになった（C-2、premium 150、堅実型生涯の発明生産比率≈75%）。カーブは単調増加で御用達が後半マイルストーンとして機能。
- **悪**: AC-10（手動優位=攻め vs 放置の週次利益率）が +10..20% を大きく超過（events込みで数千%）。再投資ドライバは攻め型のみが使い放置型が使わないため構造的に乖離。**soft 継続で honest 報告**し、P2 の #15自動値付け/#16自動発注（放置型が自動再投資できる）実装後に再校正する（M2繰越 C-3）。
- **悪**: 改訂カーブは原案より終盤の数値が大きい（御用達15Mの先も~49Mまで伸びる）。rank5(大陸商会)は MVP で disabled のため、御用達到達後は「数字の伸び」が主となる。
- **要フォロー**: (a) AC-10 再校正は #15自動値付け/#16自動発注 の自動behavior実装＋放置bot統合が前提（P2ではtracked-only flag）＝当該機能実装時に放置型へ自動再投資ノブを繋いで +10..20% へ再校正。(b) §10.3 の「商会=設備Lv5」条件は現状ランク昇格に未配線（設備Lvは実装済みなので将来ランク条件化可能）。(c) band1 発明の継続生産比率は premium 150 で ≈75%（当初監査時26%）に改善、band2/3発明（高basePrice）が入る後周回でさらに支配的になる想定。

## 検証
