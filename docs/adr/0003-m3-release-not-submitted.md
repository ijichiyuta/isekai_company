# ADR-0003: M3 リリースビルドは審査提出しない（stub IAP・課金未有効）

**状態**: 採択 / **日付**: 2026-08-26 / **関連**: 要件 §14/§16, M3 P3, ADR-0002, M3再監査(P3)

## 背景

M3 でペイウォール・IAP 境界を実装したが、実際の課金は **stub**（`app/lib/game/iap_stub.dart` の `StubIapClient`）であり、RevenueCat 連携・App Store Connect の課金プロダクト・価格・法令表示（EULA/プライバシー/特商法/資金決済法）はいずれも **M4 送り**（要件のリリース段取り）。

M3 の release ビルドをこの状態で App Store に提出すると、(a) 動作しない/未定価格の課金導線、(b) 復元対象の非消費型プロダクト不在、(c) 完全版で「解放」と謳うノードの一部が効果未配線（tracked-only、景表法リスク）——により**確実にリジェクト or 優良誤認**となる。

M3 再監査（P3）は「M3 release を審査に出さない前提を **ADR で明記**せよ」と指摘した（`m3-plan.md`・`m3-plan-audit.md` でも必須化）。本 ADR がその記録。

## 決定

1. **M3 の release ビルドは App Store 審査に提出しない**。M3 は内部検証（開発・TestFlight 内部テスト）までとし、課金は debug でのみ stub 成功する。`StubIapClient` の全メソッドは `kReleaseMode` ガードで release では `false`（AOT で定数畳み込み）。したがって release で「無料フル解放」経路は存在しない。

2. **審査提出は M4** で、RevenueCat 連携・課金プロダクト登録・価格確定・法令表示・復元動作確認を揃えてから行う（release-checklist に転記）。

3. **完全版で解放される有料ノードは、効果が実装済み（`functionalModTypes`）のもののみ購入可能**とする。未実装（種族・自動化・倍速×3・流行・劣化・離職・オフライン・ヒント/開示）は `今後有効化` 表示＋購入不可（`tryPurchaseUnlock` が拒否）。ペイウォール文言も実装済み便益（初期資金・設備・生産効率などの恒久強化）に限定し、未実装機能は「今後のアップデートで順次有効化」と明示（景表法＝優良誤認の回避）。M4 での機能実装に合わせて `functionalModTypes` に追加していく。

## 帰結

- **良**: release での無料フル解放リスクが構造的に無い（kReleaseMode 定数畳み込み＋購入経路は `purchaseFull`/`restore` のみ）。景表法リスクを未実装ノードの購入不可＋文言限定で回避。審査リジェクトの主要因を M3 時点で列挙・封じ込め。
- **悪**: M3 のペイウォールは「境界の実装」に留まり、実売価値（購入可能な有料便益）は限定的（現状の完全版 functional ノード＝初期資金III・貯えの極・商才の残響ほか）。M4 で機能実装＋課金有効化して初めてフル価値になる。
- **要フォロー（M4）**: RevenueCat 配線／課金プロダクト・価格／EULA・プライバシー・特商法・自動更新なし表記／復元 e2e／`functionalModTypes` 拡張と同時に AC-10 再校正（放置型の自動再投資、ADR-0002 要フォロー(a)）。
