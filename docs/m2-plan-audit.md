## 監査が実証した構造的事実（実走）

1. **報酬源が2種のみ・序盤集中**: 現状 rewardEvents は「発見＋昇格」だけ。steady seed1 で寿命中12件、最後がweek1139（28.5分）、以降**43分完全無報酬**。maxGap=870tick（21.75分、目標3分の7.25倍）、p90=184.5s（目標90s）。→ **AC-05 は報酬源を増やさない限り不成立**。
2. **御用達(rank4)到達率0%**: min_assets=15M に対し現状終端資産192万G（7.8倍不足）。base_demand×16・demand係数×12 でも0%。→ **AC-08 は economy 調整だけでは到達不能**。
3. **共有需要プールがid昇順ドレイン**（engine.dart sales）: 低id band1が在庫を持つ限り高id（高band/高粗利）は売れ残る。→ **engine.dart に価格/粗利/band重み付け配分が必要**（数値だけでは解決不能）。
4. **AC-10=+548%**（目標+10〜20%）: 放置型が頼る自動値付け#15・自動発注#16は**M3実装物**。M2では構造的に未達。
5. **AC-06メニュー込み実測はheadless範囲外**（Flutter/実機）。headlessの72分はトートロジー。

## 是正（計画v2への反映）

### 統合順序の組み替え（重要）
イベント(A)がAC-05の必須要素、需要プール修正が全ての前提と判明したため:
```
1) 需要プール重み付け配分の修正（engine.dart、A スコープに移管）
2) 報酬間隔計測インフラ（C, headless）＝ soft gate 先行
3) コンテンツ拡張（B、実レシピ表を確定してから）
4) イベントシステム（A）＝ AC-05の報酬ギャップを埋める
5) ゲート最終校正（C）＝ hard gate 確定
```

### ピースA 追加確定事項
- **A-D1**: contentHash に events を折り込むのは **events非空時のみ**（headless=events無 は現行4ファイルハッシュ厳密維持）
- **A-D2**: event_log・royalフラグ等の新stateフィールドは **events有効時のみ toJson 出力**（空なら key省略）。events空のcanonicalJson不変を保証
- **A-D3**: イベント抽選は **毎tick厳密2ドロー・累積重み二分探索・候補数非依存**。forcedはRNG非消費で2ドロー後に純状態上書き
- **A-D4**: royal確定発火(fame≥3000)の評価は rank-up フェーズ**より前**
- **A-D5**: EV-01〜12 を判定基準付きで明文化してから着手
- **A-D6（新規スコープ）**: **需要プールの重み付け配分**（engine.dart sales を粗利/band重み付けに）を A が担当。D-2 解消

### ピースB 追加確定事項
- **B-D1**: 実レシピ43行フル表（id, name, mat_a, mat_b, method, base_price, invention, band）を確定し、正規化(matA≤matB, method)ソートで**重複combo衝突ゼロを事前証明**（既存11＋新規32）。既存の危険combo回避: (0,0,heating)/(4,4,drying)/(6,6,grinding)/(2,2,compounding)/(0,1,cooling)/(4,7,compounding)等
- **B-D2**: 素材20種の cost 割当（§10.1レンジ1〜8）＋粗利25〜60%検算表
- **B-D3**: band1発見を寿命全体に分散させる combo配置（base_bot の (lo,hi,method) 走査順で前半集中を回避）
- **B-D4**: 石鹸(id7)は油脂×薬草のまま不変（ADR-0001）、要件§4.1例示「油脂×灰」は実装に合わせ訂正
- **B-D5**: band1 は AC-04下限35に余裕を持たせ 37〜40 に（35ちょうどは下振れでCI赤）

### ピースC 追加確定事項
- **C-D1**: **AC-10 を M2 hard gate から除外**（#15/#16=M3依存で構造的未達）。soft/informational
- **C-D2**: **AC-08 は定量裏付けが取れるまで soft**。B40種＋Aイベント収益＋需要修正で終端資産の上限見積もりを出し、届かないなら min_assets 下方修正のADRを先に切る
- **C-D3**: **AC-06 はheadlessトートロジーと明記**、実質判定はM1実機実測（繰越）。M2完了条件から切り離す
- **C-D4**: **AC-05 はイベント(A)実装後に判定**（報酬ギャップ埋めが前提）。gap=0（同tick複数報酬）の扱いとnearest-rank丸め方向を先に固定
- **C-D5**: M2 hard gate = **AC-01/02/03/04/07**（＋イベント後に AC-05）。soft/記録 = **AC-06/08/09/10**（M3で hard化を再検討）
