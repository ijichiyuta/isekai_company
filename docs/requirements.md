# 第I部 企画

## 1. プロダクト定義

### 1.1 コンセプト

過労死した現代日本のコンビニSVが異世界に転生し、行商人から大商会主へと成り上がる経営シミュレーション。前世の小売実務知識を武器に、この世界にまだ存在しない商品を発明し、市場を支配する。1周60〜90分の人生を終えると転生し、「魂の記憶」を引き継いで次の人生に挑む。

**ワンライン**: 「前世の知識で、異世界の経済を塗り替えろ。」

### 1.2 モチーフの設計根拠

| 課題 | 転生モチーフによる解決 |
|---|---|
| 周回プレイが苦痛になりがち | 「転生」がリトライを物語的に正当化 |
| メタ進行の説明が不自然 | 「前世の記憶」で自然に説明 |
| 商品開発の動機づけ | 「現代知識チート」の王道快感と一致 |
| 経営シムは絵が地味 | ファンタジー世界観で幅が出る |
| 難易度上昇の理由づけ | 転生回数に応じた「世界の難易度」設定 |

### 1.3 前世語彙のシステム転用

| システム | ゲーム内名称 |
|---|---|
| 商品開発 | **PB開発** |
| 仕入れ | **発注** |
| 在庫劣化 | **廃棄ロス** |
| 店頭配置補正 | **棚割り** |
| 販促 | **POP／季節フェア** |
| 支店戦略（v1.0） | **ドミナント出店** |
| 委任運営（v1.0） | **SV巡回／FC契約** |
| 営業時間拡張 | **24時間営業** |

隠しエンディングの一つが「異世界にコンビニを開店する」（§11.3）。前世用語は初出時にワンライン説明を付す。

### 1.4 ターゲット・ペルソナ

主要層: 25〜45歳男性（カイロソフト・放置系経営・なろう系の受容層）。副次層: 数値最適化を好む層。

| ペルソナ | 特徴 | 課金動機 |
|---|---|---|
| A: 34歳会社員 | 通勤20分×2。カイロ社アプリ購入経験 | 続きが見たい → 完全版 |
| B: 28歳最適化ガチ勢 | 攻略wikiを書く側 | 全要素を掘りたい → 完全版＋DLC |
| C: 41歳放置ゲー並行 | 1日3回×5分の回収 | 快適にしたい → 商会員パス |

**設計含意**: ペルソナAの1周は4〜5セッションに分割される。セッション分割耐性（§12.4）とオフライン進行（§17.2）はコア体験の一部。

### 1.5 想定ボリューム

| 項目 | 数値 |
|---|---|
| 1周 | 周1: 60〜90分／周2: 45〜60分（短縮設計）／周5以降: 30〜45分 |
| エンディングまで | 8〜15周 |
| コンプリート | 60〜120時間 |
| 無料範囲 | 1〜2周目・第1都市・商品60種 |

### 1.6 競合と差別化

| 競合 | 差分 |
|---|---|
| カイロソフト各作 | 転生メタ進行を中核に置く |
| Idle系 | 手動最適化が報われる（**同一状態比較の週次利益率で+10〜20%**。最終資産比では複利で×1.5〜3に増幅されることを許容） |
| なろう系IPゲーム | ガチャ非依存・買い切り。搾取疲れ層の受け皿 |

# 第II部 ゲーム仕様

## 2. 進行方式

### 2.1 セミリアルタイム

| 項目 | 値（調整初期値） |
|---|---|
| 1ティック | ゲーム内1週 |
| 1年 | 48週（4季×12週）＝72秒 |
| 標準速度 | 1.5秒/ティック |
| 寿命 | 60年＝2,880ティック（**第一調整変数**。M1でメニュー込み実測し周1を60〜90分に収束） |
| 倍速 | ×2（完全版）／×3（魂の記憶#14） |
| 一時停止 | 常時可。イベント・管理画面・季節/流行切替で自動ポーズ |
| バックグラウンド | 自動ポーズ＋オートセーブ→オフライン進行（§17.2） |

**予約制（ティック量子化・必須）**: 値付け・発注・フェア・配置は「翌週反映」の予約制。APM を要求する操作を作らない。報酬間隔の受け入れ条件は×1速実時間で定義（付録A）。

### 2.2 決定論的コアと禁止則（最大の技術的勝ち筋）

コアは pure Dart。「状態＋コマンド列＋シード → 次状態」の決定論処理。UIは再生層。

**禁止則（lint＋CIで強制）**
1. コア内の数値は**64bit整数固定小数点**。`double`・`dart:math`超越関数を禁止（カーブは整数テーブル/多項式近似）
2. コア内 `HashMap`/`HashSet` 禁止。順序走査は**エンティティID昇順**
3. コア内 `DateTime`/`Stopwatch` 禁止。時刻はコマンド入力値
4. 外部由来の資金・アイテムは**grantコマンド**として記録（オフライン報酬・IAP特典）
5. 乱数は自前PRNG（PCG32）を**システム別ストリーム**分割、消費カウンタをセーブに保存
6. リプレイ一致テストは **ubuntu(x64)/macos(ARM64) 両ランナー**で状態ハッシュ照合
7. リプレイ互換範囲は「同一ビルド＋同一balanceハッシュ」内（セーブに記録）

## 3. コアループ（3層）

```
第1層(1〜3分): 発注 → PB開発・生産 → 棚割り・値付け → 利益 → 再投資
第2層(1周):    行商人→露店→店舗→商会→王国御用達→大陸商会 → 人生終了 → 生涯評価
第3層(全体):   評価 → 魂の記憶pt → 恒久アンロック → 有利な次の人生
```

**原則**: 「1分後の報酬」「10分後の昇格」「次の人生での解放」が常に同時に見える。メイン画面に次ランク進捗と「次の区切りまで◯分」を常設（§12.3）。

## 4. 商品開発「PB開発」

### 4.1 合成式（全仕様共通）

`素材スロット2 ＋ 製法スロット1（＋品質任意スロット1）= 商品`

- **製法（MVP 8種）**: 冷却／加熱／発酵／乾燥／粉砕／精密加工／縫製／調合。設備に紐づく所持リスト。初期設備は「冷却」を含む（チュートリアルのプリンを保証）
- 品質任意スロット: 追加素材で★+1（例: プリン＋砂糖）
- 例: プリン＝小麦×卵＋冷却／石鹸＝油脂×灰＋調合／ベアリング＝鉄×鉄＋精密加工

### 4.4 発明・品質・廃棄ロス

- **発明判定**: 発明レシピの初回開発時。一時金＝**基準売値×25**、名声＝**基準売値×2.5**（調整初期値。プリン: 売値12G→+300G/+30名声）。住民驚愕演出（§12.5）
- **品質**: MVP ★1〜★3（v1.0で★5）。品質→売値倍率: ★1=×1.0／★2=×1.3／★3=×1.7。職人スキルと品質素材で決定
- **廃棄ロス**: 劣化週数超過で在庫が廃棄に。目標廃棄率帯 5〜15%（下回る=生産不足、上回る=作りすぎ、のシグナルとしてUI表示）。魂の記憶#10で劣化速度-30%

## 6. 市場・価格

- **需要供給**: 商品×都市の需要量。供給過多で価格下落
- **流行（調整初期値）**: 都市あたり平均96週（2年）に1回。**予告4週（自動ポーズ＋計画ダイアログ、設定でオフ可）→ 持続8〜12週、需要×2〜3**。MVPは同時1件。魂の記憶#9=予告リード2倍＋カテゴリ・倍率の詳細開示
- **季節**: 対象カテゴリ需要±30〜50%。切替時に自動ポーズ＋来季予告
- **値付け**: 手動（翌週反映の予約制）。適正価格からの乖離で購買率変動（適正±0%=100%、+30%=60%、-20%=130%等の応答曲線をbalanceで定義）
- **自動値付け**: 適正価格固定（初心者救済）。手動（流行・季節を織り込む）が週次利益率+10〜20%になるよう設計。魂の記憶#15で自動が流行考慮に強化
- 借入はMVP非実装

### 8.2 生涯スコア（調整初期値）

```
生涯スコア = 資産×α + 累積名声×β + 発見レシピ×γ + ランク係数δ + 実績×ε
           × 世界難易度倍率 × 修羅の道倍率 × 縛り倍率(v1.0)
α=1pt/10万G, β=1pt/10名声, γ=20pt/種, δ=(行商0/露店50/店舗150/商会400/御用達1000/大陸2500), ε=30pt/個
```
周1想定獲得: 約2,500pt（資産150＋名声300＋レシピ800＋ランク1000＋実績300）→ 2〜3項目購入可。

### 8.3 世界難易度

- MVPのレバー=税率加算: **転生1回ごとに+1.5%、10回でカンスト（+15%）**。以降上昇しない
- 受け入れ条件: カンストまで勝率が緩やかに単調改善、以降横ばい（AC-10）

## 17. 機能要件

### 17.1 セーブ（方式確定）

- **GameSave本体＝単一ブロブ**: 一時ファイル→fsync→アトミックリネーム＋SHA-256＋3世代ローテーション。破損時は直前世代から自動復旧＋通知
- **高頻度セーブ＝スナップショット＋コマンドジャーナル**: フルスナップショットは「ポーズ/バックグラウンド/昇格/ゲーム内年」ごと、間はコマンド追記。復旧＝スナップショット＋再生（決定論が復旧機構）
- **Drift＝追記型専用**（歴代・図鑑・分析キュー）。GameSaveに使わない
- schema_version＋全過去版フィクスチャのマイグレーションテストCI（極めて重要）。手動スロット3
- **クラウドセーブ＝v0.9**: メタ進行は単調マージ（和集合/最大値）で無損失統合、currentLifeのみユーザー選択。匿名→Apple ID連携の衝突フロー定義。アカウント削除同時実装

### 17.2 オフライン進行

- **ティック非消費**。蓄積額＝退出時点の週次純利益×経過実時間×**20%**。**1回受取上限＝次ランク昇格資産閾値の10%**
- 時間上限: 無料4h／パス12h／#20で+2h。受取は**grantコマンド**
- 経過時間は「被害上限設計」: {壁時計, uptime}アンカー→同一ブートはuptime差分を信頼→再起動検出時は壁時計clamp(0,上限)→残存不正は「再起動1回=上限1回分」と受容。購入・パス特典はサーバー時刻必須。**オフラインプレイは一切ブロックしない**
